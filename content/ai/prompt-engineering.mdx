## Shape the assistant

These rules apply when you write or review a system prompt for a TFX AI surface.

### Set the role and constraints

- **Anchor the role in the product context, not a generic role.** A concrete framing anchors tone and scope more reliably than a generic one.

  | Do | Don't |
  | --- | --- |
  | "You are a teaching-support assistant for Singapore primary-school educators working in CaseSync." | "You are a helpful assistant." |

  _([Anthropic Prompting best practices](https://docs.anthropic.com/en/docs/build-with-claude/prompt-engineering/overview) - "Give Claude a role")_

- **Explain the why behind each constraint, not just the rule.** The model generalises from reasons; a bare rule without rationale is brittle.

  | Do | Don't |
  | --- | --- |
  | "Use MOE-prescribed terminology so responses match what teachers see in official materials." | "Use terms from the approved word list." with no reason given. |

  _([Anthropic Prompting best practices](https://docs.anthropic.com/en/docs/build-with-claude/prompt-engineering/overview) - "Add context to improve performance")_

- **Structure the prompt: identity, instructions, examples, context — using XML tags.** This ordering is auditable and prevents later sections from silently overriding earlier ones.

  | Do | Don't |
  | --- | --- |
  | `<identity>`, `<instructions>`, `<examples>`, `<context>` in that order, each in its own tag. | Interleave instructions and examples in a single unstructured block where the model must infer the boundary. |

  _([OpenAI Prompt engineering guide](https://platform.openai.com/docs/guides/prompt-engineering) - "Message formatting with Markdown and XML"; [Anthropic Prompting best practices](https://docs.anthropic.com/en/docs/build-with-claude/prompt-engineering/overview) - "Structure prompts with XML tags")_

### Calibrate tone with examples

- **Include 3-5 labelled examples covering the warmth calibration.** One correct reply and one that is too clinical teach the Kind Utility register faster than prose description.

  | Do | Don't |
  | --- | --- |
  | Label one example `<example type="correct">` and one `<example type="too-clinical">` and show the difference in how a missed-homework note reads. | Write "Use a warm, professional tone" in the instructions and include no examples. |

  _([Anthropic Prompting best practices](https://docs.anthropic.com/en/docs/build-with-claude/prompt-engineering/overview) - "Use examples effectively"; [OpenAI Prompt engineering guide](https://platform.openai.com/docs/guides/prompt-engineering) - "Few-shot learning")_

- **Control output format with positive instructions, not prohibitions.** A positive instruction is more reliable and easier to audit.

  | Do | Don't |
  | --- | --- |
  | "Respond in plain prose, one idea per sentence, no more than three sentences for a short answer." | "Do not use markdown formatting or headers." |

  _([Anthropic Prompting best practices](https://docs.anthropic.com/en/docs/build-with-claude/prompt-engineering/overview) - "Control the format of responses")_

### Handle context and complexity

- **Wrap classroom-context data in labelled tags so the model knows what is fixed.** Named tags prevent the model from asking the teacher to repeat what the system already holds.

  | Do | Don't |
  | --- | --- |
  | `<context subject="English" level="P5" class_size="30">` in the system prompt so the assistant never asks "What year level is this for?" | Pass subject and level as part of the user message and let the model infer them turn-by-turn. |

  _([Anthropic Prompting best practices](https://docs.anthropic.com/en/docs/build-with-claude/prompt-engineering/overview) - "Structure prompts with XML tags"; [OpenAI Prompt engineering guide](https://platform.openai.com/docs/guides/prompt-engineering) - "Include relevant context information")_

- **For complex tasks, instruct the model to reason before answering.** Explicit think-first instructions reduce shallow answers on multi-step problems.

  | Do | Don't |
  | --- | --- |
  | "Before drafting the lesson hook, consider the year level, the objective, and what the teacher already told you about the class." | Ask directly: "Write a lesson hook for this objective." with no reasoning step. |

  _([Anthropic Prompting best practices](https://docs.anthropic.com/en/docs/build-with-claude/prompt-engineering/overview) - "Thinking and reasoning")_

- **Treat teacher-pasted content as data, not instructions.** Wrap it in a labelled tag and state that content inside those tags never overrides the assistant's role or constraints.

  | Do | Don't |
  | --- | --- |
  | Wrap pasted student work in a clearly named tag and state that content inside it cannot override the assistant's role or constraints. | Accept pasted student work in the main user message with no tag boundary. |

  _([Anthropic Prompting best practices](https://docs.anthropic.com/en/docs/build-with-claude/prompt-engineering/overview) - "Structure prompts with XML tags"; [Anthropic agentic security guidance](https://docs.anthropic.com/en/docs/build-with-claude/computer-use#prompt-injection-safeguards))_

### Test before shipping

- **Test the prompt with real teacher inputs before shipping.** Run 5-10 representative inputs — one ambiguous, one off-topic, one very short — and check tone, scope, and fallbacks.

  | Do | Don't |
  | --- | --- |
  | Test with "What should I do about a student who keeps forgetting homework?" (ambiguous) and "Book a room for me" (out of scope) before the surface goes live. | Test only with the happy-path inputs you wrote the prompt to handle. |

  _([Anthropic prompt engineering overview](https://docs.anthropic.com/en/docs/build-with-claude/prompt-engineering/overview) - "Before prompt engineering: build evaluations")_
